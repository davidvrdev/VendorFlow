# VendorFlow - Developer setup (Windows)

Requirements: JDK 21+ (JDK 25 works; bytecode is compiled with `release=21`), Docker Desktop running. No global
Maven: use the Maven Wrapper in `backend/`.

## Backend

### Git Bash
```bash
docker compose up -d postgres            # from the repo root
cd backend
./mvnw verify                            # tests (Testcontainers starts its own Postgres; Docker must be running)
./mvnw spring-boot:run                   # API on http://localhost:8080 (profile "local")
curl -i http://localhost:8080/actuator/health
```

### PowerShell
```powershell
docker compose up -d postgres
cd backend
.\mvnw.cmd verify
.\mvnw.cmd spring-boot:run
Invoke-WebRequest http://localhost:8080/actuator/health -UseBasicParsing
```

### Docker image (optional)
```bash
cd backend && docker build -t vendorflow-api:dev .
docker run --rm -p 8080:8080 -e DATABASE_URL=jdbc:postgresql://host.docker.internal:5432/vendorflow \
  -e DATABASE_USERNAME=vendorflow -e DATABASE_PASSWORD=vendorflow-local vendorflow-api:dev
```

### Troubleshooting
- **`Unable to establish loopback connection` when starting Tomcat (JDK 25 on Windows)**: the JDK's NIO selector
  uses a Unix-domain socket in the temp dir, which can fail on some machines. Workaround: point it at a short,
  writable directory, e.g. `mkdir C:\vf-tmp` and run with `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:/vf-tmp`
  (Git Bash: `export JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:/vf-tmp`). Tests using MockMvc are not affected.
- Tests need Docker Desktop running (Testcontainers pulls `postgres:17-alpine` the first time).

## Frontend

Requirements: Node 24, npm 11.

```bash
cd frontend
npm ci                                   # first time / after lockfile changes
cp .env.example .env.local               # BACKEND_URL=http://localhost:8080 (optional: that is the default)
npm run dev                              # http://localhost:3000 ; /api/* is proxied to the backend
npm run lint && npm run typecheck && npm test && npm run build
npx playwright install chromium          # first time only
npx playwright test                      # E2E (starts `npm run dev` itself)
```

Notes:
- `frontend/AGENTS.md` (generated by create-next-app, re-added by `next dev`) tells agents to read the bundled
  Next.js docs in `node_modules/next/dist/docs/` before using Next APIs — Next 16 differs from older versions
  (async `cookies()`, `retry()` in `error.tsx`, typed `LayoutProps`).
- After `npx shadcn add <component>`, check imports use `@/lib/utils` (shadcn 4.21 once generated `from "cn"`).
- `shadcn` is a devDependency: only its CSS is used, at build time.

## Full local stack
1. `docker compose up -d postgres` (repo root)
2. `cd backend && ./mvnw spring-boot:run`
3. `cd frontend && npm run dev` → open http://localhost:3000
